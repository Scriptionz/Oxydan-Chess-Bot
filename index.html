What's new in v12

Highlights from the v11.0 → v12.0 refactor.

FIX Reliable in-game chat

  • New oxydan_chat.py module replaces the silent except TypeError: pass branches that dropped every message.
  • Every chat send is logged with chat: ✔ / chat: ✘ in the bot log.
  • Stats endpoint (oxydan_chat.attempted / success / failed) for monitoring.

FIX Tournament auto-join

  • Scan interval decoupled from join cooldown: tournament_scan_interval (45s) vs tournament_cooldown (120s).
  • Local registered tournaments cache (12h TTL) prevents re-joining the same event.
  • Better handling of "already in a tournament game" via _is_in_tournament_game.

NEW Master-level time management

  • Four layers: panic (<2s) → transition (2-12s) → opening (first 10 plies) → complexity (past move 30).
  • Configurable via time_management: in config.yml.
  • Defaults tuned for bullet, blitz and rapid on Ethereal.

NEW Fork-friendly config

  • Single config.py with typed Settings dataclass — no more two SETTINGS dicts drifting apart.
  • config.yml follows Lichess-bot spec + Oxydan extensions; every key has a default.
  • python lichess-bot.py --self-test validates config + engine in 5 seconds.

EXP Oxydan Learn

  • Tracks every opening played in oxydan_learn.json with win / loss / draw counts.
  • Book selection is re-weighted by the bot's own history (win lines boosted, loss lines deprioritised).
  • Off by default — flip oxydan_learn.enabled: true in config.yml.

NEW Diagnostics & observability

  • Engine pool, chat and matchmaking share a single oxydan.* logger namespace.
  • OXYDAN_LOG_LEVEL=DEBUG for verbose traces, OXYDAN_VERBOSE_BERSERK=1 to unhide berserk logs.
  • Stdout reconfigured to UTF-8 so Windows consoles don't crash on emoji.

ChangeLog (latest)

Full history in ChangeLog.md on GitHub.

[12.0] — August 22, 2026

Added

  • config.py — single source of truth for every runtime knob (typed Settings dataclass, deep-merged with config.yml).
  • oxydan_chat.py — branded chat engine with stats, retry, and explicit logging. The previous version's except TypeError: pass branches silently dropped every message; that's fixed.
  • oxydan_learn.py — experimental opening book weighting based on the bot's own win/loss history (opt-in via oxydan_learn.enabled).
  • Master-level time allocation in OxydanV12._allocate_time: panic / transition / opening / complexity bands, all configurable.
  • --self-test flag to validate config.yml + engine without connecting to Lichess.
  • UTF-8 stdout reconfiguration so logs render correctly on Windows consoles.

Changed

  • Matchmaking: tournament auto-join now scans every 45s but joins at most every 120s. Local 12h cache prevents re-joining the same event.
  • Two legacy SETTINGS dicts (in lichess-bot.py and matchmaking.py) consolidated into config.Settings.
  • Engine wrapper class renamed OxydanV11 → OxydanV12; the previous name lives on as a thin alias in check_bot.py for back-compat.
  • config.yml reorganised to follow the Lichess-bot spec for engine / challenge_policy / matchmaking with Oxydan extensions in dedicated blocks.

Fixed

  • Chat messages were silently dropped because the fallback path tried post_message(..., room="player") which is not a valid berserk parameter. New ChatSender only uses the documented spectator= kwarg.
  • Greeting chat was sometimes sent before Lichess opened the game chat (state was created). Now it is deferred to the first gameState event after the game is officially started.
  • Move parse used parse_san first; Lichess streams moves in UCI, so the parser now goes straight to parse_uci.
  • Matchmaker's _is_in_tournament_game previously only checked get_ongoing(); it now also tracks locally joined tournaments to skip redundant work.

Challenge Protocol

Elite bots

  • 2300+ rating accepted in rated games.
  • Standard and Chess960 are supported.
  • Time controls from bullet to classical are allowed.

Protection rules

  • Low-rated bots are routed to safer casual games.
  • Opponent repeat limits protect rating and variety.
  • Matchmaking can enter protection mode after rating drops.

Core Capabilities

Engine stack

  • Ethereal-based UCI engine pipeline.
  • NNUE evaluation with opening book support.
  • Safer time management for increment games.

Operations

  • Auto-abort for inactive opponents.
  • Fallback move selection if the engine fails.
  • Optional chat and post-game messaging.
